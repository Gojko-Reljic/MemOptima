# MemOptima 0.9.0 Scope

## Purpose

MemOptima 0.9.0 hardens the terminal rendering boundary for artifact-derived cgroup paths and makes
the finality of public evidence-stream callbacks explicit. It is a focused production-quality and
security release; it adds no new monitoring or intelligence feature.

## Terminal Rendering Contract

`memoptima trends analyze <MANIFEST>` and `memoptima forecast evaluate <MANIFEST>` render the
artifact-derived `CGROUP PATH` table cell through one shared internal CLI formatter.

| Original byte or sequence | Display text |
|---|---|
| `\\` | `\\\\` |
| newline | `\n` |
| carriage return | `\r` |
| tab | `\t` |
| Any other ASCII control byte, including ESC and DEL | `\xHH` with uppercase hexadecimal digits |

The transformation is display-only. MemOptima preserves the original cgroup path for artifact
validation, strict identity comparison, epoch selection, and all analysis. Ordinary printable paths
retain their existing terminal output.

The rule does not apply to Docker container IDs, CLI headers, or status text: those values are either
strictly validated or generated by MemOptima rather than supplied by the artifact.

## Public Evidence Stream Contract

`ArtifactSink::consume` receives validated events while traversal is in progress. Those callbacks
are provisional: a later input, validation, or I/O failure can cause
`traverse_artifact_beneath` to fail after some callbacks have already run.

The evidence module does not roll back callback effects. A consumer that writes durable state or
performs an external action must stage its effects and commit them only after traversal returns a
successful result. This rule does not change the existing in-memory trend and forecast-evaluation
consumers, which discard their accumulated work on failure.

## Validation

The release adds tests for newline, carriage return, tab, escape, DEL, and literal-backslash display;
unchanged ordinary paths; both affected formatters; and the documented provisional callback
semantics. It preserves the Debug sanitizer suite, Release suite, Release Valgrind check, format and
whitespace checks, and the authorized Docker cgroup v2 integration check.

## Non-goals

Version 0.9.0 does not change the schema-version-1 evidence format, reject artifacts solely because
a cgroup path contains a control byte, normalize identity values, alter other CLI tables, add a
daemon or dashboard, diagnose a memory leak or anomaly, predict OOM, recommend a configuration
change, or modify a host, container, or cgroup.
