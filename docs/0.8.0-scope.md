# MemOptima 0.8.0 Scope

## Purpose

MemOptima 0.8.0 adds read-only temporal holdout evaluation for the existing evidence-based
`memory.current` forecast model. It measures how an eligible historical projection compares with
the immediately following observed memory sample from explicitly selected local evidence artifacts.

It does not introduce an OOM prediction, memory-leak diagnosis, anomaly diagnosis, risk score,
automatic recommendation, or automatic action.

## Public Command

```text
memoptima forecast evaluate <MANIFEST>
```

The command uses the existing schema-version-1 trend manifest and writes one human-readable summary
and table to standard output. The existing `memoptima forecast evidence <FILE>` command remains
unchanged.

| Exit code | Meaning |
|---:|---|
| `0` | A valid report was produced, including an empty report. |
| `1` | Manifest, catalog, replay, analysis, formatting, or output failed. |
| `2` | Command usage is invalid. |

## Evaluation Boundary

The evaluator has one strict identity: full Docker container ID plus cgroup path. It derives an
independent current-memory epoch for that identity. Available `memory.current` values and strictly
increasing capture times are required for continuity; a changed, unlimited, or unavailable
`memory.max` does not break it.

For a compatible epoch, evaluation selects the first usable history containing at least three
observations across at least ten seconds. The immediately next observation is the holdout. This
avoids evaluating a projection against data that was already used to make it.

Incomplete evidence is shown with `excluded incomplete session` and is excluded from eligibility,
coverage, MAE, and bias. All other unavailable cases receive a stable row status rather than an
unsupported conclusion.

## Output and Safety Contract

The report contains eligible and evaluated counts, coverage, mean absolute error, signed bias,
incomplete-session exclusions, nonzero status counts, and one row per observation epoch. The row
includes the forecast and holdout timestamps, projected and actual current memory, signed error,
and status.

A valid manifest that yields no container epochs writes:

```text
No forecast evaluation epochs found in manifest.
```

and exits successfully without a table. Processing preserves the established bounded manifest
limits: at most 128 artifacts and 4,096 active observation epochs. Any unsafe path, malformed
artifact, lifecycle inconsistency, or processing failure fails the complete report instead of
producing partial output.

## Non-goals

Version 0.8.0 does not add a daemon, database, directory scan, dashboard, alerts, JSON report,
PSI/swap/cache model, alternative forecast model, logical identity across redeployments, leak
detection, anomaly detection, OOM prediction, workload-health certification, recommendation, or
host/container/cgroup modification.

The accuracy evidence produced here is intended to inform later predictive and intelligence work;
it is not proof that a workload is safe or unsafe.
