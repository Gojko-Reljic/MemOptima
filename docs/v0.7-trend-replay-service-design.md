# MemOptima v0.7 Trend Replay Service Design

## Purpose

This document specifies the application layer that turns a validated `TrendManifest` into one
complete `TrendAnalysis`. It connects the existing manifest, session catalog, typed evidence
projection, and pure analyzer without adding a CLI command, changing schema-v1 evidence, or
authorizing an automatic system action.

## Boundary and ownership

```text
TrendManifest (public)
    -> TrendEvidenceCatalog (public)
    -> typed evidence replay adapter (internal)
    -> TrendAnalyzer (public)
    -> TrendAnalysis or TrendAnalysisError (public)
    -> future CLI and presenters
```

The service is public because multiple higher layers need the same use case. The typed evidence
reader, replay sink, path traversal, and metadata comparison remain implementation details in
`src/trends`. The service does not parse manifest JSON, format terminal output, construct JSON
reports, discover Docker containers, or alter the host.

## Public API

The public header is `include/memoptima/trends/trend_analysis_service.hpp`.

```cpp
enum class TrendAnalysisErrorCode {
    catalog_failed,
    evidence_replay_failed,
    analyzer_failed,
};

struct TrendAnalysisError {
    TrendAnalysisErrorCode code;
    std::optional<std::filesystem::path> artifact_path;
    std::string detail;
};

[[nodiscard]] std::expected<TrendAnalysis, TrendAnalysisError>
analyze_trend_manifest(const TrendManifest &manifest);
```

`detail` is an English diagnostic for a human or log. Callers use `code` and, when present,
`artifact_path` for stable programmatic handling. The service has no partial-success state: an
error result contains no `TrendAnalysis`.

The API accepts an already parsed `TrendManifest`. The manifest loader and parser preserve their
existing contracts; command-line argument parsing and manifest-file loading belong to the future
CLI layer.

## Processing sequence

1. Call `load_trend_evidence_catalog(manifest)`. A catalog failure becomes `catalog_failed`.
2. Create one `TrendAnalyzer` for the whole ordered catalog.
3. For each `TrendEvidenceSession`, stream the artifact again using the internal typed evidence
   reader. The replay sink first collects the catalog-comparison metadata while forwarding valid
   events to the analyzer in their original input order.
4. After a successful traversal, compare replay metadata with the first-pass catalog entry. A
   mismatch returns `evidence_replay_failed` before a result can be returned.
5. Call `TrendAnalyzer::end_session` with the traversal's `incomplete` result only after the
   traversal and metadata comparison succeed. A typed-reader failure or an analyzer event failure
   maps to the appropriate error category.
6. After all cataloged artifacts replay successfully, call `TrendAnalyzer::finish()` and return its
   complete `TrendAnalysis` or an `analyzer_failed` error.

The implementation must not call `finish()` after any error or manufacture a partial result from
epochs accumulated before that error.

## Event mapping

For each artifact, the adapter preserves the typed-reader event order exactly:

| Typed evidence event | Analyzer action |
| --- | --- |
| session start | `begin_session({ started_at, requested_interval_ms })` |
| sample | `begin_sample({ captured_at })` |
| container observation | `observe({ identity, current_memory_bytes, maximum_memory })` |
| end of typed sample | `end_sample()` |
| successful traversal result | `end_session({ incomplete })` |

An artifact without a terminal evidence record is a valid incomplete artifact when the shared
reader accepts it. It has no typed end event, yet its traversal result reports `incomplete = true`.
The adapter closes its analyzer session from that result, preserving the analyzer's lifecycle and
marking contributed epochs as incomplete.

## Catalog/replay consistency check

Cataloging is intentionally a first streaming pass. Replaying the named pathname is a second pass,
so the service must not assume that the artifact still represents the session that was cataloged.
For each artifact, it compares the following semantic metadata with the corresponding
`TrendEvidenceSession`:

- session start timestamp;
- requested sampling interval;
- incomplete status;
- the set of strict container identities; and
- each identity's minimum and maximum captured timestamps.

Timestamps use the canonical representation already produced by the shared evidence path. A window
minimum and maximum are the temporal bounds across all samples for one identity, not the first and
last timestamps in artifact input order. Identity comparison uses the full Docker container ID and
cgroup path. A missing, additional, or changed window is a mismatch. The check protects the session
ordering and non-overlap decisions derived by the catalog.

v0.7 intentionally does not hash full artifact contents. A hash would add a new artifact-integrity
contract and still requires a defined lifecycle for files that change between validation and use.
The bounded metadata check addresses the facts on which trend selection depends; the replay's typed
metrics remain the actual analyzer input.

## Failure mapping

| Condition | Service error |
| --- | --- |
| Session catalog cannot validate, order, or admit the manifest artifacts | `catalog_failed` |
| A replayed artifact cannot be read or validated | `evidence_replay_failed` |
| Replay metadata differs from its catalog session | `evidence_replay_failed` |
| The typed event sequence is rejected by `TrendAnalyzer` | `analyzer_failed` |
| `TrendAnalyzer::finish()` fails | `analyzer_failed` |

Every failure preserves the responsible artifact path when one exists. Neither `detail` nor an
error category changes the evidence artifact format or the future CLI output contract.

## Test requirements

The service tests must cover at least:

- a successful analysis across ordered complete and incomplete artifacts;
- catalog failure for an invalid selected artifact;
- replay failure from an artifact that changes in catalog-relevant metadata between passes;
- typed-reader failure during replay;
- analyzer failure propagation from an invalid adapter event, using an internal test seam or a
  directly tested pure adapter component; and
- no partial `TrendAnalysis` returned for every failure category.

Tests for the pure metadata comparator must include changed start time, interval, completion state,
identity set, and both bounds of an observation window. The test strategy must not expose the
internal typed reader as a public production dependency solely to create failures.

## Safety and non-goals

The service is read-only. It changes no cgroup, kernel, Docker, process, or evidence file state.
It reports observed trend analysis only. It does not forecast an OOM event, diagnose a memory leak,
classify an anomaly, recommend a resource limit, send an alert, or take an automatic action.
