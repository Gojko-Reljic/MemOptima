# MemOptima 0.9.1 Scope

## Purpose

MemOptima 0.9.1 is a focused security and trust-boundary patch. It closes remaining terminal-rendering
exposure in evidence and manifest workflows after v0.9.0 safely rendered artifact-derived cgroup
paths only in the trend and forecast-evaluation tables.

## Known Issues in Earlier Releases

Version 0.9.0 escapes ASCII control bytes only in the CGROUP PATH cells of trends analyze and
forecast evaluate. It does not provide equivalent protection for inspect evidence, forecast evidence,
or diagnostics that can render untrusted artifact, manifest, path, or filesystem text.

The v0.9.1 release notes will state this boundary clearly. A GitHub Security Advisory may be prepared
as a draft during the patch and published together with the verified release, subject to owner
approval.

## Evidence Validation Contract

Schema version 1 remains unchanged. The v0.9.1 validator adds these constraints:

- Each container ID contains exactly 64 hexadecimal ASCII characters. Uppercase and lowercase
  hexadecimal characters are accepted, matching the Docker ID parser.
- Each application version contains from 1 through 64 printable ASCII bytes, inclusive of 0x20
  through 0x7E.
- Fields represented internally as uint32_t, including requested sample count and sample sequence,
  must not exceed UINT32_MAX.

These are intentional compatibility constraints. Artifacts produced by every MemOptima writer to
date comply. Artifacts with arbitrary IDs, terminal-control version text, or overflowing unsigned
values are invalid evidence and must be rejected rather than displayed or narrowed.

Duplicate JSON-key rejection is deferred to v0.10 because it requires an explicitly selected parsing
policy and parser-level verification. It must be completed before Intelligence features begin.

## Terminal Rendering Contract

One internal CLI display transformation will be used whenever untrusted text reaches standard output
or standard error. It applies to artifact fields, manifest paths, command-line paths repeated in
output, filesystem diagnostics, and live cgroup-directory warnings.

| Input | Display text |
|---|---|
| Literal backslash | \\ |
| Newline, carriage return, tab | \n, \r, \t |
| Other C0 controls and DEL | \xHH, uppercase hexadecimal |
| C1 controls | \u{...}, uppercase hexadecimal |
| Bidi, zero-width, line, and paragraph controls | \u{...}, uppercase hexadecimal |
| Invalid UTF-8 byte | \xHH, uppercase hexadecimal |
| Other valid printable Unicode | Unchanged |

The transformation is display-only. Valid original values remain unchanged for filesystem handling,
strict identity comparison, evidence validation, and analysis.

## Command Coverage

The patch covers terminal output and diagnostics in:

- inspect evidence;
- forecast evidence;
- trends analyze;
- forecast evaluate;
- live Docker or cgroup warnings that include cgroup-directory text.

The four artifact-reading commands require an end-to-end CMake test with poisoned JSON and manifest
fixtures. The test must check both standard output and standard error and prove that raw C0, C1,
bidi, zero-width, and line-separator controls do not pass through.

## Non-goals

Version 0.9.1 does not add a public trusted-text type, normalize identity values, alter evidence
schema version 1, add a daemon or dashboard, change forecasting mathematics, diagnose an anomaly or
memory leak, recommend a configuration change, or modify a host, container, or cgroup.

## Release Requirements

The patch requires Debug and Release test suites, sanitizer checks, Release Valgrind, formatting and
whitespace checks, the authorized Docker cgroup v2 integration check, and an approved CodeRabbit
review. A public GitHub Security Advisory, if used, is published only with owner approval after the
patch is released.
