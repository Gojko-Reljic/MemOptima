# MemOptima 0.6.0 Scope

## Purpose

MemOptima 0.6.0 derives a conservative estimate of time to a finite cgroup `memory.max` from a
validated local evidence artifact:

```text
memoptima forecast evidence <FILE>
```

It is Linux-only, local, read-only, and never contacts Docker, `/proc`, a network service, or a
container while forecasting.

## Evidence requirements

A container forecast requires at least three observations over at least ten seconds of actual
`captured_at_utc` time. The container must appear in every sample, provide `memory.current` and a
stable finite `memory.max` in every observation, and have strictly increasing timestamps.

The model uses linear regression for the average growth rate, then calculates remaining time from
the latest observed `memory.current` value. It reports an explicit unavailable reason when evidence
is incomplete, discontinuous, too short, non-growing, or has a changing or unavailable limit.

`memory.max: "max"` is reported as **not applicable**, not as a collection failure.

## Safety boundary

The result estimates a crossing of `memory.max`; it is not an OOM prediction, memory-leak
diagnosis, workload-health certification, recommendation, or automatic action. It never changes
cgroup limits, kernel configuration, containers, or files.
